# To-Do List

## Просветова Вероника Михайловна, ФИТ-241

### Описание проекта

To-Do List на Vue 3, TypeScript и Vite. Состояние организовано через Pinia с сохранением в `localStorage`, переходами между страницами управляет Vue Router, а качество кода и стиль контролируются через ESLint и Prettier.

### Запуск проекта

Используемая версия Node.js - - - v24.13.0

1. Установите файлы проекта с репозитория.
2. Перейдите в папку проекта и установите зависимости по lock-файлу:

```bash
npm ci
```

3. Запустите режим разработки или соберите и откройте предпросмотр готового приложения:

```bash
npm run dev
```

или для проверки итоговой сборки:

```bash
npm run build
npm run preview
```

4. После запуска откройте ссылку из терминала (обычно `http://localhost:5173/` для `dev` или `http://localhost:4173/` для `preview`).

### Команды проверок и форматирования

- `npm run type-check` — проверка типов приложения и шаблонов через `vue-tsc`, а также конфигурации Vite через `tsc`.
- `npm run lint` — проверка кода линтером ESLint без предупреждений и ошибок.
- `npm run lint:fix` — автоматическое исправление замечаний ESLint.
- `npm run format:check` — проверка форматирования файлов через Prettier.
- `npm run format` — автоматическое форматирование исходников, конфигов и документации.
- `npm run check` — запуск всех статических проверок (`type-check`, `lint`, `format:check`) без изменения файлов.
- `npm run build` — запуск `npm run check` и последующая сборка проекта через Vite.

### Как работают проверки перед сборкой

Команда `npm run build` сначала выполняет `npm run check`. Если на этапе проверки типов, линтера или форматирования возникнет хотя бы одна ошибка или предупреждение, сборка остановится и папка `dist/` не будет создана.

**Чем проверка типов отличается от сборки Vite:** Vite только преобразует TypeScript в JavaScript, отбрасывая аннотации типов ради быстрой сборки, но не проверяет их корректность. Статический анализ типов выполняют `vue-tsc` (для `.ts`-файлов и шаблонов `.vue`) и `tsc` (для `vite.config.ts`).

### Эксплуатация и проверка учебных данных

Вся авторизация является сугубо имитационной и хранит данные в `localStorage` браузера — не используйте ваши реальные пароли.

1. **Сохранность данных после переноса:** если в браузере уже сохранены пользователи и задачи из предыдущей версии (лабораторная работа №7), они автоматически восстановятся без изменения формата.
2. **Проверка защиты маршрутов:** при попытке открыть прямую ссылку `/#/` без авторизации сработает guard и перенаправит на `/#/login`.
3. **Проверка аккаунтов и задач:** зарегистрируйте нового пользователя или зайдите под готовым учебным пользователем, добавьте/отредактируйте задачи, отметьте часть выполненными (они перечеркнутся, станут серыми и уйдут вниз списка), перезагрузите страницу (`F5`), выйдите и войдите снова — все задачи пользователя сохранятся и останутся изолированными от других аккаунтов.
